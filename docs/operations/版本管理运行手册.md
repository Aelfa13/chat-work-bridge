## Validation baseline gates

### UPSTREAM_BASELINE_GATE

`main` 是纯 upstream-sync baseline。同步或发布到 `origin/main` 前，必须确认：

- `main` 与 `upstream/main` 精确相同；
- 工作区 clean；
- main 没有个人治理或业务提交；
- upstream CI contract 为 `ubuntu-latest`、Node.js 22、`npm test`。

Windows port 开发采用人工 gate：

上游 CI 当前不覆盖 Windows；Windows 结果不能替代 upstream baseline gate。

## Git 规则

开发只发生在 development 或 feature/fix 分支。提交、推送、合并、标签、发布和 production closure 是不同动作，不能因为 transport 可用就自动放开。

远端证明使用真实 Git transport：

~~~text
git remote -v
git ls-remote --heads <remote> refs/heads/<development-branch>
~~~

API、tracking ref、本地 HEAD 和本地 status 都不能代替远端证明。远端异常、认证失败、host key 异常、超时或 non-fast-forward 时 fail-closed。

## 安全门

- 变更前确认工作区和恢复点；
- 变更后审查范围、测试和状态；
- 清理前后检查 Git 状态；
- 不用 reset、force push、git clean 或通配符删除恢复“干净”；
- 清理优先 move 到隔离目录。

## Production comparison

比较顺序固定为：

~~~text
presence
→ raw SHA-256
→ text-only EOL-normalized SHA-256
→ binary raw SHA-256
~~~

Binary 不通过换行规范化放行。未知 presence、未分类代码/static resource 差异和 binary raw mismatch 均阻塞。

预期差异只能写入：

docs/operations/production-drift-allowlist.yml

并逐项包含 path、class、reason、owner、reviewed_at。禁止使用“全部 systemd/dotfile/metadata/config/binary”之类的宽泛规则。
